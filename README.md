# PostmortemPilot

PostmortemPilot turns an unstructured incident bundle (chat, logs, tickets) into an evidence-linked, blameless postmortem and a DRAFT remediation ticket. It is a LangGraph pipeline around a hosted `Qwen/Qwen3-8B` model (<=8B) with deterministic Python guardrails.

## Architecture

```
bundle -> triage -> timeline/RAG -> drafter -> critic
             |            |            |          |
        CLARIFY/REFUSE   DuckDB     report +    evidence IDs,
        /ABORT routing   log search + runbook    section, blame and
                         /past-PM retrieval      timeline checks;
                                                 loop back to drafter
                                                 (max 2 revisions)
```

- **Triage** (`src/agent/graph.py: triage_node`): redacts secrets, parses/normalises timestamps to UTC, quarantines prompt-injection lines, and routes `PROCEED`, `CLARIFY`, `REFUSE`, `FOLLOWUP`, `ERROR`, or `ABORT`.
- **Timeline/RAG** (`investigator_rag_node`): DuckDB `search_logs` over the incident window plus hybrid BM25 + dense retrieval over runbooks and past postmortems (`src/retrieval/hybrid_rag.py`).
- **Drafter**: assembles the 7-section report, runbook gap, evidence IDs, and a DRAFT ticket. With live LLM synthesis enabled it asks the model for one summary sentence; otherwise it uses a deterministic template.
- **Critic**: rejects missing sections, blame lexicon, invalid/outside-window evidence IDs, and lexical non-overlap between root cause and cited evidence.

HITL export is gated by `src/governance/guardrails.py` (`prepare_hitl_ticket` / `export_ticket_if_approved`). A ticket is only `APPROVED_FOR_EXPORT` after explicit human confirmation.

## Setup

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env       # fill in chat + embedding endpoint values
```

`src/llm.py` reads `UNI_API_KEY` / `UNI_BASE_URL` / `UNI_MODEL_NAME` (or `OPENAI_*` / `MODEL_NAME` aliases) and `EMBEDDING_*`. `.env` and `certs/` are gitignored. If the embedding endpoint is unavailable, `EMBEDDINGS_LOCAL_FALLBACK=1` switches to deterministic local hash embeddings so retrieval still runs offline.

## Run

```bash
streamlit run app/streamlit_app.py     # SRE workbench UI
pytest -q                              # unit / safety / robustness tests
.venv/bin/python -m src.week3_eval     # 80-query eval -> results/runs/*.csv + trace.jsonl
.venv/bin/python -m src.eval_retrieval # retrieval sweep -> results/retrieval_experiment.csv + week2_retrieval_recall.csv
```

`src/week3_eval.py` deletes and recreates `results/runs/trace.jsonl`; `src/eval_retrieval.py` rewrites the two retrieval CSVs.

## Known caveats

- Numbers above are from the tracked result files, not re-run for this README.
- The retrieval corpus used by the app is `data/corpus/sre_corpus.jsonl` (581 docs). `data/corpus/corpus.jsonl` (2,000 docs, seed 42) is the generated corpus described in `docs/CORPUS.md`.
- The Docker image was not built or verified locally for this submission.
- Live-LLM runs depend on the external university endpoints and private CA certs in `certs/`; without them the deterministic fallbacks are used and latency/quality differ.
